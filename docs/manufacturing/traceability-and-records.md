# Unit, configuration and evidence traceability

Document `MFG-02`, revision 0.2, 2026-09-08. **Reference procedure; no serials issued, devices provisioned or calibration performed.** Implements the traceability portion of REQ-MFG-001, REQ-SEC-001 and REQ-LIFE-001; addresses HAZ-002, 005–007, 010–015 and 017. Physical activities require separate authorization.

## 1. Reference binding and record integrity

The populated reference is `reference-v1`, revision `HW-REF-1.1`, default `passive_monitor`, from [hardware/interfaces/reference-v1.json](../../hardware/interfaces/reference-v1.json). Its status is `PROVISIONAL_REFERENCE_NOT_FOR_FABRICATION`. No firmware release or physical calibration is nominated by this document. The existing local monitor/replay software is not proof of a manufactured unit or secure production provisioning; its local access key is not a device factory credential.

Revision review, 2026-09-08: explicitly rebound to `HW-REF-1.1` for source-verified pin mappings, corrected battery/panel envelopes and the withdrawn panel-discontinuation interpretation; [MFG-01 records the changes](reference-build-and-eol.md). Procurement availability, installed configuration and physical qualification remain unresolved. No new physical approval or performed record is introduced.

[unperformed-records.json](templates/unperformed-records.json) is a forms bundle with populated project references and explicit null results. Its `is_template: true`, `status: not_performed`, null actual identities/dates/results and empty physical evidence lists are deliberate. Do not fill or relabel these source forms to resemble completed factory records. For authorized future work, create separate controlled records outside the template source, assign actual identities and preserve this blank master. A record store, numbering authority, retention period, authorized reviewers and access policy must be approved before real collection; no live factory record store is established here.

Each real record must distinguish `reference_review`, `software_test`, `simulation`, `vendor_source`, `independent_review`, `physical_test` and `field_test` evidence. These are evidence classes, not an automatic ladder: a vendor rating does not become a Poseidon physical-test pass; a reviewer signature does not manufacture a missing test. Physical data require actual specimen, method, calibrated equipment, raw data and independent acceptance.

Use separate execution and acceptance states. A future execution can be planned, blocked, in-progress, performed or aborted; acceptance remains null until reviewed, then records pass/fail or a justified not-applicable decision. An aborted or incomplete test cannot pass. A not-applicable decision identifies variant, rationale and reviewer; it is not a generic exemption for an unknown component. No null measurement means zero, no empty evidence list means passed, and no simulated identity may enter an actual batch denominator.

Record UTC time with source/time quality, operator identity, method/version, input/output hashes, deviations and reviewer identity/date. Hash references name algorithm (SHA-256), byte size, content digest, artifact location and access custodian; the digest verifies bytes, not scientific truth. Keep raw records immutable, with amendments linked to the original and reason; never replace failed results with retest output. Restrict personal/site data and secrets, use controlled backups, test restoration and retention/deletion rules, and record access. Do not upload records or exact site coordinates from this tranche.

## 2. Identity and as-built chain

Manufacturing quality owns uniqueness and the serial format before any unit is issued. Serial allocation must be transactionally unique across stock, WIP, scrap, service and returns; retired/scrapped serials cannot be reused. Board supplier serials and radio identifiers are not automatically Poseidon unit serials. Unknown component lots stay explicit and block the relevant traceability gate.

| Record link | Required actual fields | Population rule |
|---|---|---|
| Work order to unit | Approved phase/quantity/variant, order ID, unit serial, parent/child serials, custody/location, creation authority | No issued identifiers in templates. Distinguish complete unit from replaceable wet head, REEF and hub. |
| Unit to materials | BOM revision/hash; part/manufacturer/revision; supplier, purchase/receipt ID, lot/date code/serial; quantities installed/removed/scrapped | Preserve supplier-to-unit forward trace and unit-to-lot reverse trace, including replacements and split lots. |
| Unit to physical design | Drawing/EDA/wiring/interface/assembly instruction revisions and hashes; approved ECO/deviation IDs; assembly/tool/fixture processes | Reference CAD plus a matching part name is not an as-built record. |
| Unit to software | Hardware target/revision; hub image/container/package digest; firmware digest; build/source and dependency lock/SBOM references; signature verification and key-policy reference | Separate intended, installed, verified and recovery image versions. Do not assert a release tag for uncommitted reference software. |
| Unit to configuration | Canonical configuration bytes/hash/version; schema; variant/population; calibration references; enabled functions; approved change record | Secrets live outside ordinary configuration exports. Any safety-relevant value change requires impact review. |
| Unit to security | Device public identity/certificate serial or fingerprint, key-management reference, provisioning event/operator/station, policy/version, rotation/revocation/recovery history | No raw private key, symmetric key, bootstrap token, seed, password, join secret or recovery secret in records, logs, QR labels, screenshots or repository. |
| Unit to calibration | Chain ID and all component serials, certificate/report/version, method, measured coefficients/units, uncertainty/conditions, validity basis and reviewer | Unknown, expired, changed-chain or out-of-tolerance calibration prevents a calibrated claim; it cannot be supplied by a nominal datasheet sensitivity. |
| Unit to acceptance/service | Full traveler, incoming reports, first and repeat EOL attempts, NCRs/rework, qualification applicability, packaging, authorization and custody/service history | History survives resale, repair, module swap and scrapping. No shipment record without a separately authorized real shipment. |

A forward-trace query must identify every unit touched by a failed supplier lot, fixture calibration interval, firmware/configuration release or credential-policy event. A reverse-trace query must recover a unit's complete as-built and as-maintained lineage. In a later PVT drill, choose real known records, reconcile all hits and gaps, and preserve the query input, results and reviewer decision. A synthetic query drill remains simulation, not proof of a real supply chain.

## 3. Provisioning and firmware station handoff (`PROV-01`)

**Owners:** security owner defines identity/key policy and revocation; firmware/platform owners define target and signed/recoverable build; manufacturing quality validates station and record linkage. This is an unperformed procedure, not a provisioning implementation or permission to flash equipment.

1. Before authorizing a station, approve credential generation/storage boundaries, hardware secure storage where selected, per-device identity uniqueness, least privilege, operator authentication, station software/image hash, audit logging without secrets, backup/recovery and compromised-station response. Define access segregation and independent review suitable for a solo owner with specialist support. Missing key management or firmware release blocks the station.
2. Bind the actual unit and board target to an approved work order. Validate exact hardware target, image digest/signature, signing policy/version, security rollback floor, configuration/calibration revision and known-good recovery route before installation. Pin the approved inputs; do not install `latest`.
3. Generate/provision unique device secrets only inside the authorized key-management boundary and transport. Record opaque key reference or public certificate fingerprint and a non-secret operation receipt, never raw keys or a hash of a low-entropy secret as a substitute. Production secrets are not reused for simulation or all units. LoRaWAN identifiers and joins must use the later approved regional/network plan; no radio operation occurs now.
4. Verify installed image/configuration identity and device-bound authentication under an approved test. Record positive and negative cases (wrong target, unauthorized identity, duplicate identity, expired/revoked credential) and failure disposition without disclosing challenge secrets. Physical secure-boot and recovery behavior require actual device evidence; host tests alone cannot close them.
5. On interruption or uncertain provisioning state, quarantine the unit and transaction. Reconcile identity reservation and partial writes through the approved recovery path; do not mint an untracked second identity or downgrade below the security floor. On suspected key exposure, contain the station, identify affected serials, revoke/rotate through the security process and repeat authorized validation.
6. Final review binds actual installed versions, public identity/key reference and non-secret receipt to the traveler. Remove temporary bootstrap authority and approve station cleanup through the security policy. Record disposal/revocation of unused identities. Preserve failed attempts in first-pass/yield accounting when the batch definition includes this station.

Signature verification is not a calibration, electrical safety or acoustic authorization. Every restart/recovery preserves the passive variant and never automatically rearms a future output path.

## 4. Calibration lineage (`CAL-01`)

**Owners:** underwater-acoustics/acquisition specialists for receive/timing chains; electrical/instrument specialists for power/probes; qualified facility for reference measurements. Hardware `PV-09` owns the physical method. No calibration constants, tolerance, interval or certificates are invented here.

Before calibration, freeze measured quantity, units and reference, range/band, geometry, sample rate/gain/filter/clock settings, environmental conditions, uncertainty model, traceability route, acceptance/guard-band rule, recheck interval and authorized method. Record reference instrument serials, certificate identifiers/hashes and due/validity status. Digital full-scale amplitude alone is not underwater pressure; record calibrated pressure/exposure units only when the full chain and uncertainty support them.

For each actual run preserve as-found and as-left values, raw samples, adjustment history, coefficients and units, calibration software/configuration digest, method/fixture, chain components/cables and serials, temperature and other required conditions, technician, reviewer and report hash. Calibration validity is tied to the exact chain and approved use conditions. A calibration certificate can state uncertainty without proving fitness for the intended measurement; the specialist accepts that separately.

A hydrophone/DAQ/probe/cable/gain/filter/clock change, enclosure/wet-head repair, suspect drift, out-of-calibration reference instrument or relevant firmware change triggers impact review. The specialist decides full/partial recalibration and retrospective impact on recorded data, not manufacturing convenience. Preserve superseded calibration and mark affected data/units, stop calibrated claims while unresolved, and link the new version without rewriting old provenance. An overdue certificate never silently extends its own validity.

## 5. Engineering and service changes (`ECO-01`)

An engineering change identifies reason, old/new part/software/configuration/process, affected serial/lot/release range, hazards/requirements, supplier documentation, inventory/WIP/field containment, requalification matrix, calibration/security effects, cost/lead time and independent approvals. The user separately approves spending or commercial action.

At minimum, boundary/seal/window/penetrator changes require mechanical pressure/leak review; battery/converter/cable/fuse changes require power/protection/thermal/EMC review; radio/antenna changes require regional/spectrum/conformity review; receive/clock changes require data/calibration review; firmware/key/update changes require security/fault/recovery review; intended use/site/output/claims changes require safety/ecology/permissions/compliance review. No supplier substitution is equivalent solely because a connector mates.

Update the as-maintained record after authorized service and preserve the previous as-built state. The responsible specialists define affected acceptance tests before work; an unknown rework or service limit blocks return to service. A repaired unit passing EOL does not retrospectively clear its original field incident or authorize redeployment at an unapproved site.
