# Tranche 3 digital backend interface

Status: endpoint/DTO milestone. These additive `/api/v1` routes preserve recording, companion and lifecycle v1 routes. All commands simulate software state only. No MQTT publication, device dispatch, output or production key custody exists.

## Identity and roles

Existing `POST /principals` now accepts the explicit single role `operator` alongside viewer/reviewer/admin/device. Only an admin can enroll a scoped operator; enrollment records `principal.enroll` in the audit. Admin is not operator. All command kinds require an active scoped operator, a matching principal-bound signing key and site scope. The local-development key cannot sign commands or implicitly rearm. Existing `GET /identity` fields remain unchanged. `GET /command-context/{device_id}` returns `{principal_id,device_id,allowed_kinds,sequence_seen,keys}` for a scoped operator, including its active CommandKey objects. No credential hashes or private keys appear.

## Command and key endpoints

- `GET /command-keys`: `{items: CommandKey[]}` in caller scope. Operator sees own keys; admin sees keys wholly within its site scope.
- `POST /command-keys`: `{key_id, principal_id, public_key_hex}`. Active scoped operator enrolls its own 32-byte Ed25519 public key (64 lowercase hex characters); scoped admin may enroll a key for an operator wholly in its scope. Returns CommandKey with `site_ids`, `created_at`, `revoked_at`; creation/revocation audited. Private key never sent to server.
- `POST /command-keys/{key_id}/revoke`: empty body, same ownership/scope rule.
- `GET /commands?limit=50&offset=0`: `{items:[{command,ack}],total,limit,offset}` scoped by site/device.
- `POST /commands`: exact signed Command JSON, `Content-Type: application/json`. Optional `X-Poseidon-Retained: true` marks forbidden retained delivery; false or absent is normal. Returns Ack, HTTP 200 for semantic accepted/rejected/expired/duplicate/executed/failed outcomes; malformed wire data returns existing HTTP error DTO. The exact incoming UTF-8 body is preserved for retry identity. Unique-key JSON only. Authentication failure remains HTTP 401; out-of-scope reads remain 404.
- `GET /commands/{command_id}`: `{command,ack}`.
- `GET /command-sequence/{device_id}`: `{device_id,principal_id,sequence_seen}` for the authenticated operator, decimal text, initially `"0"`.

Command: `{schema_version:"poseidon.command.v1",command_id,site_id,zone_id,device_id,principal_id,key_id,sequence,issued_at,expires_at,kind,params,signature}`. `command_id` is lowercase UUID4; IDs use `[A-Za-z0-9][A-Za-z0-9._-]{0,127}`. Sequence is canonical uint64 decimal **text**, first accepted sequence >0. UTC timestamps use `Z` and at most millisecond precision. Lifespan must be positive and <=600 seconds. Params canonical JSON <=4096 bytes. Closed kind set: inhibit, resume, rearm, clear-fault, wiper-run, health-request, config-apply. No `target_state`. Params are `{}` except config-apply, which uses `{config:<versioned config>}`. Wiper-run returns executed with an explicit digital-simulation reason; it never operates a wiper. Config-apply stores only validated digital config.

`signature` is `{algorithm:"Ed25519",canonicalization:"poseidon-json-v1",value:<base64 64-byte signature>}`. Sign **all Command fields except signature**, using existing `poseidon_proto.signing.signing_bytes(payload,key_id)`: ASCII bytes `poseidon.signed-manifest.v1`, NUL, key_id, NUL, poseidon-json-v1 canonical JSON. Canonical JSON escapes non-ASCII UTF-16 code units as lowercase `\uXXXX`, sorts keys by Unicode code point, has no whitespace and no float-valued numbers. New TS helper exports `canonicalJson`, `signingBytes`, `parseCommand`, `parseCommandAck`. Browser creates a non-extractable Ed25519 private key with WebCrypto in memory; public key is exported and enrolled. Reload loses private key; enroll a new key, do not promise production custody.

Ack: `{schema_version:"poseidon.command-ack.v1",command_id,device_id,received_at,outcome,reason,state_after,sequence_seen}`. Outcome enum accepted/rejected/expired/duplicate/executed/failed; reason bounded 256 chars; state_after observe/armed/inhibited/fault (emit reserved, unreachable). Sequence_seen canonical uint64 decimal text. Local execution is synchronous, so a valid accepted command returns executed or failed; accepted is reserved for another validated digital consumer. A valid byte-identical retry returns duplicate without transition or execution, after current key/role/scope/expiry checks. Other non-increasing sequences reject. A failed execution consumes its accepted sequence. Commands and acks are never retained.

## Registry, health, alarms and state

- `PUT /devices/{device_id}/health-profile`: admin; `{schema_version:"poseidon.device-health-profile.v1",zone_id,stale_after_s,offline_after_s}` with positive integer stale < offline <=86400. Explicit zone required. Profile is immutable after enrollment; identical retry allowed. `GET` same route returns profile or 404. No inferred zone/profile for legacy devices.
- `GET /device-health?limit=50&offset=0`: `{items:[{device_id,site_id,zone_id,health,last_telemetry_at,age_s,profile}],total,limit,offset}`. Health is online/stale/offline/revoked/unprofiled, based on actual accepted nonduplicate telemetry receipt and its declared delivery age. Registry presence does not prove connection. No telemetry means offline once profiled; no profile means unprofiled.
- `GET /hub-state`: `{state,simulation:true,emission_enabled:false,binding,watchdogs,last_transitions}`. `binding` is null until `PUT /hub-binding` with `{device_id}` by the local-development admin explicitly pins an active registered `kind:hub`, synthetic device with an enrolled health profile; it then contains `{device_id,site_id,zone_id}`. Binding is immutable (identical retry allowed), audited and never inferred from registry order. `GET /hub-binding` reads this binding. State reads require bound-site scope; unbound state is readable by local-development admin only. State-changing commands must target this exact binding; other devices never change workspace state. Transitions newest first, at most ten, each `{id,from_state,to_state,cause_id,command_id,reason,created_at}`. Watchdog DTO is a list of `{id,healthy,reason}`. No public direct state setter or fault-injection endpoint.
- `GET /alarms?limit=50&offset=0`: `{items:[{id,source,site_id,device_id,severity,reason,opened_at,cleared_at,acknowledged_by,acknowledged_at}],total,limit,offset}`. Source is hub or device. Severity warning or critical. Open/clear/ack audited. Acknowledging is not clearing.
- `POST /alarms/{alarm_id}/acknowledge`: empty body, scoped operator or admin, returns alarm.

State semantics: inhibit observe/armed to inhibited (cannot clear fault); resume inhibited to observe; rearm observe to armed only scoped operator and all watchdogs healthy; clear-fault fault to inhibited only operator after fault alarms acknowledged. Any entry to emit refuses. Restart never armed: clean close restores observe, unclean restores inhibited. Fault alarms remain visible across restart.

## Calibration and retention seams

`GET /calibrations?limit=50&offset=0` returns `{items:[{record,validity}],total,limit,offset}`; validity current/expired/not_yet_valid/superseded. `POST /calibrations` accepts an immutable signed digital-only record, operator only. `GET /calibrations/{record_id}` returns `{record,validity}`. Exact record fields: `{schema_version:"poseidon.calibration-record.v1",record_id,supersedes_id,instrument_id,quantity,unit,method,reference_id,value,uncertainty:{value,coverage_factor},valid_from,valid_until,operator_id,source_documents,key_id,digital_only:true,signature}`. Record IDs are safe identifiers, supersedes_id nullable, instrument_id is an active registered device, operator_id is the enrolled principal ID. value and both uncertainty fields are canonical decimal TEXT (no exponent, leading plus/zero, trailing fractional zero or negative zero; uncertainty>=0, coverage_factor>0). source_documents is a bounded list of lowercase SHA256 strings. Signature metadata/scheme match commands, signing all record fields except signature. Predecessor must exist for the same instrument and quantity, chain must remain acyclic, a predecessor has at most one successor. Supported UCUM subset is exactly `1`, `%`, `Cel`, `K`, `Pa`, `kPa`, `m`, `s`, `Hz`, `V`, `mV`, `A`, `W`, `mg/L`, `g/L`, `m/s`, `dB`, `[pH]`; all other text rejects. This is a declared unit, not physical calibration evidence. No edit/delete record routes. Expired records remain readable but cannot be newly enrolled or used as current calibration.

Retention is opt-in, no automatic deletion. `GET /retention-policy` requires admin. `PUT /retention-policy` requires local-development admin and exact `{schema_version:"poseidon.retention-policy.v1",media:{enabled,max_age_s},companions:{enabled,max_age_s}}`; enabled is boolean, age is integer 1..315360000. Response adds `eligible_after:{media:<UTC|null>,companions:<UTC|null>}`. Server watermarks prohibit selecting any pre-policy user/campaign evidence. Disabling/re-enabling resets that class's watermark forward. Only newly admitted, completed **synthetic** recordings may be selected; no age/cutoff comes from the client.

`POST /retention/preview` requires admin, exact `{recording_ids:[<id>],data_classes:["media"|"companions"]}` with unique IDs, 1..32 recordings. Both class names may be selected together. All selected bytes must already be expired, known and untampered. Response Plan is `{schema_version:"poseidon.retention-plan.v1",plan_id,state,created_at,approved_by,approved_at,executed_at,recording_ids,data_classes,items,policy,sha256}`; state preview/approved/executing/executed. Items have `{recording_id,data_class,site_id,device_id,source_sha256,manifest_fingerprint,files,documents}`. Files have `{path,sha256,bytes,device,inode}` with relative owned paths (never request-supplied). Companion documents have `{role,name,byte_count,sha256}`; companion items also have projection_sha256/projection_bytes. Media items also have manifest_sha256.

`POST /retention/plans/{plan_id}/approve` and `/execute` each require admin, exact `{sha256:<preview sha256>}`. Scope, policy, ages, all hashes and file inode identities are rechecked before deletion. No DELETE route or implicit expiration worker exists. Execution deletes selected WAV/video files and/or original companion document BLOBs plus projection bytes. Manifests and source/catalog hashes remain. Every preview/approval/deletion writes an audit. An interrupted executing plan fails catalog integrity on reopen instead of repairing evidence or claiming completion.

`GET /retention/tombstones/{recording_id}` uses recording scope, returns `{recording_id,items:[<item fields plus schema_version:"poseidon.retention-tombstone.v1",plan_id,deleted_at,state:"expired",complete_evidence:false>]}`. Deleted media leaves the recording out of the available recording list; direct recording/waveform/video reads return 410. Companion projection/document reads return 410 after either supporting media or companion deletion. Tombstones never turn deleted data into valid/complete evidence. Existing user/campaign evidence predating explicit opt-in is never eligible.
